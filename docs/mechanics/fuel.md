# Топливо: дневник и калькулятор

Статус: готово

## Зачем

На вкладке «Топливо» — справочник КБЖУ и дневник за сегодня. Тон без вины: цифры как ориентир, не как оценка.

## Справочник

Значения на **100 г съедобной части**. Клиент: `src/features/calories/foods.js`. Сервер сводит базы в `server/nutrition.js`.

Локальная таблица `data/content/foods.json` — обычные продукты без штрихкода. Источники таблицы: Скурихин / Тутельян, 2002; Смолянский, 1984; USDA. PDF в репозиторий не кладём.

Правила разбора локальной таблицы:

- диапазон вроде `235-262` → середина
- прочерк и «следы» → 0
- алкоголь — отдельная категория, в UI без акцента

Живой поиск (от 2 символов) и штрихкод дополнительно тянут:

- Open Food Facts world + ru — магазинные пачки, русские названия
- USDA FoodData Central — Foundation / SR Legacy (обычные) и Branded (US-штрихкоды)

Дубли по имени и коду склеиваются. Nutritionix / FatSecret / витрины магазинов не подключаем: нужны ключи и парсинг. Свой ключ USDA — `USDA_API_KEY` в `keys/.env`, иначе `DEMO_KEY` (лимит запросов).

Расчёт порции: `ккал = ккал100 × граммы / 100`. То же для белков, жиров, углеводов.

## Норма на день

`src/features/calories/target.js`. Mifflin–St Jeor по текущему весу, росту, возрасту и полу (`sex`: `male` / `female`):

- базовый обмен: `10×кг + 6.25×см − 5×лет`, затем `+5` (м) или `−161` (ж)
- активность из `daysPerWeek`: 1–2 → 1.375, 3–5 → 1.55, 6–7 → 1.725
- разница желаемый − текущий вес:
  - ±0.5 кг → поддержание
  - худеть → минус `clamp(|Δ|×40, 200, 500)` ккал, не ниже 1500 (м) / 1200 (ж)
  - набирать → плюс то же, не больше +400

Без пола в профиле — среднее смещение (−78) и подсказка указать м/ж.

## Дневник

В JSON пользователя:

```json
"fuelLog": {
  "date": "2026-09-25",
  "items": [
    { "id": "log-…", "foodId": "yabloki", "grams": 150, "label": "Яблоки", "kcal": 71, "protein": 0.6, "fat": 0, "carbs": 15 }
  ]
}
```

Пишем `foodId` + `grams` и снимок `label` / КБЖУ — если справочник поправят, старые записи не «поплывут».

Календарный день — **UTC**, как серия на MVP. Если `date` не сегодня, сервер отдаёт пустой список.

`PATCH /me` принимает `fuelLog`, секреты не возвращает.

## Арена

На главной те же цель / съедено. Тап открывает Топливо.

## Экран

1. Плашка: съедено / цель ккал, заполнение, Б/Ж/У. Если выше цели — «сегодня плотнее ориентира».
2. Поиск, чипы категорий и **сканер** штрихкода.
3. Карточка продукта: КБЖУ на 100 г, счётчик граммов (− / + шаг 10, 10–500), «В дневник».
4. Список приёмов: имя, граммы, ккал, убрать.

## Сканер

Кнопка «Сканер» на Топливе. Камера в браузере телефона (лучше **https** / `npm run share`) читает EAN через ZXing. Если камеры нет — поле с цифрами с пачки.

Сервер: `GET /barcode/{код}` — ru Open Food Facts, затем world, затем USDA по GTIN. `GET /foods/search?q=` — локальная таблица + OFF ru/world + USDA. КБЖУ на 100 г, дальше тот же счётчик и `fuelLog` (`foodId` вида `off-…` / `usda-…`). Нет в базах — другое слово или цифры с пачки. Ориентир, не этикетка суда.
